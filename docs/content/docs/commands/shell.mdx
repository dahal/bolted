---
title: bolt shell
description: Open an interactive shell inside the Bolted VM (not a container).
---

Drops you into an interactive shell **inside the Bolted VM** — at the VM level, not inside any particular repo's dev container. Use this for VM-wide debugging, manual `apk` installs, inspecting `/bolted/repos`, etc.

For a shell scoped to a repo's dev container, use [`bolt dev <repo>`](/docs/commands/dev) instead.

## Synopsis

```sh
bolt shell
```

No flags today.

## Examples

```sh
bolt shell
# /bolted/repos # ls
# api  web
# /bolted/repos # exit
```

## What happens

1. Verify Bolted is initialised, the VM is running, and the volume is unlocked.
2. Refuse if stdin isn't a TTY — an interactive shell on a closed stdin is just a wedged process.
3. Exec `/bin/sh` (or the shell configured via `bolted.yaml`, once that lands) inside the VM with TTY allocation.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Shell exited cleanly |
| `1` | Generic error (stdin not a TTY, exec failed) |
| `2` | Bolted not initialised, VM not running, or volume locked |
| _other_ | Whatever exit code the shell itself returned |
