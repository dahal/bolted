Rotates the LUKS passphrase atomically. Prompts for the current password, verifies it, adds a new keyslot with the new password, verifies the new slot unlocks, then removes the old slot. Data is not re-encrypted.

If the keychain integration is enabled (`keychain: true` in `~/.bolted/config.yaml`), the stored secret is updated after the rotation succeeds.

<Callout>
  Also available as **`bolt passwd`** - Unix tradition. Both names are identical; pick whichever
  your fingers prefer.
</Callout>

## Synopsis

```sh
bolt password      # primary
bolt passwd        # alias, identical behaviour
```

No flags.

## Examples

```sh
bolt password
# Current Bolted password:
# New Bolted password:
# Confirm new Bolted password:
# Bolted password changed.
```

## Safety

`bolt password` is designed so a mid-flight failure never locks you out:

1. Verify current password (no changes if wrong).
2. Add the new keyslot. Both passwords now work.
3. Verify the new keyslot. On failure, bail without removing the old slot - re-run `bolt password`.
4. Remove the old keyslot. If this fails, both passwords still work - re-run.

<Callout type="warn">
  There is still no recovery if you forget both passwords. Store the new one before exiting the
  terminal.
</Callout>

## Exit codes

| Code | Meaning                                                                  |
| ---- | ------------------------------------------------------------------------ |
| `0`  | Rotated successfully (keychain update failures are warnings, not errors) |
| `1`  | Generic error (keyslot add/remove failed)                                |
| `3`  | Wrong current password                                                   |
