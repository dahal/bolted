This page walks you from "nothing installed" to "running a dev container against a real repo" inside an encrypted Linux VM. Plan on about five minutes.

<Steps>

<Step>

### Install the CLI

<Tabs items={['macOS', 'Windows']}>
<Tab value="macOS">

```sh
curl -fsSL https://raw.githubusercontent.com/dahal/bolted/main/install.sh | sh
```

The installer drops Bolted and a `bolt` symlink into `$HOME/.local/bin`. Override the location with `BOLTED_PREFIX=$HOME/bin` and pin a version with `BOLTED_VERSION=v0.1.2`.

<Callout type="info" title="Add ~/.local/bin to your PATH">
  If `$HOME/.local/bin` isn't already on your shell's `PATH`, add this line to
  your shell rc (`~/.zshrc` / `~/.bashrc`):

  ```sh
  export PATH="$HOME/.local/bin:$PATH"
  ```

  `install.sh` prints this exact line when it detects the gap. Bolted
  deliberately doesn't auto-edit your shell config - a `curl … | sh`
  that silently rewrites `~/.zshrc` is exactly the kind of pattern
  Bolted is positioned against.
</Callout>

</Tab>
<Tab value="Windows">

Windows binaries are shipped as a zip. The shell installer doesn't run on Windows - download the archive instead:

1. Grab `bolted-<version>-windows-amd64.zip` from the [releases page](https://github.com/dahal/bolted/releases).
2. Extract `bolt.exe` somewhere on your `PATH` (for example `%USERPROFILE%\bin`).
3. Optionally create a `bolt.exe` copy or shim so you can use the short alias.

</Tab>
</Tabs>

Confirm the install:

```sh
bolt version
```

</Step>

<Step>

### Initialise Bolted

`bolt init` creates the encrypted volume, sizes a VM from your hardware, and writes `~/.bolted/config.yaml`. You'll be prompted to set a password - twice.

```sh
bolt init
```

<Callout type="warn" title="No password recovery">
  Lose this password and you lose the volume's contents. That's the point. Store it in a password
  manager before you forget it.
</Callout>

</Step>

<Step>

### Unlock the volume

`bolt unlock` boots the VM (if it isn't already running), opens the LUKS volume, and mounts it at `/bolted/repos`. You'll be asked for the password you just set.

```sh
bolt unlock
```

When you're done for the day:

```sh
bolt lock
```

`lock` unmounts the volume and evicts the key from the VM's kernel keyring. After this, the bytes on disk are ciphertext again. The VM keeps running by default so the next `unlock` is fast - pass `--stop-vm` to shut it down too.

</Step>

<Step>

### Clone a repo into the volume

Anything that isn't a reserved `bolt` subcommand is passed through to the VM. `git`, `gh`, `gcloud`, `kubectl` and friends just work:

```sh
bolt git clone https://github.com/octocat/Hello-World.git
```

The repo lands in `/bolted/repos/Hello-World/` inside the encrypted volume. The host filesystem never sees the plaintext.

List what you have:

```sh
bolt ls
```

</Step>

<Step>

### Start a dev container

`bolt dev <repo>` brings up the repo's dev container (using its `.devcontainer/devcontainer.json` if present, or a sensible default) and drops you into a shell:

```sh
bolt dev Hello-World
```

From the host you can run one-shot commands without attaching a shell:

```sh
bolt exec Hello-World ls -la
```

When you're finished, stop the container (the repo data is untouched):

```sh
bolt stop Hello-World
```

</Step>

<Step>

### Lock up

```sh
bolt lock
```

That's the loop: `unlock` → work → `lock`.

</Step>

</Steps>
